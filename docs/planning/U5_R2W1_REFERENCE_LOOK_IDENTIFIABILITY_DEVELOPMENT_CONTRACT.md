# U5.R2W1 Reference-Look Identifiability Development Contract

Date: 2026-07-27

Status: **complete; paired upper bound only, output-only methods fail**

## Parent and purpose

U5.R2W1D is a sibling research leaf under U5.R2. It follows the U5.R2W0
source/method audit, U5.R2O0's validated explicit flow and the negative
identifiability evidence from U5.R2S1-S3.

Execution waits for S4's repeated formal decision and, when that S4 branch
activates U1, U1's repeated formal decision. An S4 branch that correctly
prevents U1 does not scientifically block W1; it must instead leave an
explicit U1-nonactivation record. S4/U1 outcomes do not permit rewriting this
already frozen W1 contract.

It asks one narrow question:

> Can a fixed, non-generative representation recover the same known bounded
> colour operator from references with unrelated content, and does one
> reference contain enough information or are multiple same-look references
> required?

This is a generated development experiment. It does not use or authorize
film pixels, current quarantined photographs, FiveK images, professional
grades or owner preference labels.

## Why this differs from marginal matching

S1-S3 tried to infer an operator from one or more unpaired colour
distributions and found content-dominated or non-identifying solutions. W1
instead supplies supervised **look identity and operator truth during
development**, generated by applying each known O0 operator to several
independent contents.

The practical query still does not receive the neutral reference counterpart.
The paired-reference method is retained only as a synthetic upper bound. This
separation prevents an easy paired solution from being reported as evidence
for output-only reference matching.

## Generated groups

The complete machine-readable values are frozen in
`configs/u5_r2w1_reference_look_identifiability_development_v1.json`.

The repeat-exact formal decision is `paired_upper_bound_only_passes`; see
`docs/U5_R2W1_REFERENCE_LOOK_IDENTIFIABILITY_DEVELOPMENT_RESULTS.md`.

### Look families

Development interleaves 16 palette-score and 16 independently smoothed random
O0 velocity directions. Directions `0-23` are the fit/retrieval-bank
partition and directions `24-31` are the development unseen-direction
partition; interleaving gives both partitions both generator families. Four
bounded strengths (`.35`, `.50`, `.72`, `1.00`) are generated on each
direction, yielding 128 operator instances. Each strength is interpolation in
velocity parameter space from exact identity, never a blend of final RGB.

An additional explicit regression fixture maps the owner anchors
`53/55/56` to one direction at strengths `.72/.50/.58`. The method must not
turn that strength path into three categorical modes.

Twenty-four entirely different base directions from a third preregistered
monotone-curve-plus-positive-matrix family are reserved for confirmation and
are inaccessible during development. A development pass confined to the two
development families is therefore not yet cross-family confirmation.

### Content and nuisance groups

Each operator instance is rendered over eight independent generated content
groups. Groups `0-3` are the fit/bank partition and groups `4-7` are held-out
queries; any ridge regularization choice uses group cross-validation inside
`0-3`. The single-reference score uses each held-out group separately and the
four-reference score aggregates groups `4-7` symmetrically. A content group
contains several bounded Gaussian-mixture scenes and is held out as a unit.
Source and reference groups never share samples, scenes, palettes or random
streams.

Each reference also receives a bounded pre-look exposure/WB/basic-tone
nuisance drawn independently by content group. Its parameters are known only
to the generator and paired upper bound. Output-only methods see only the
final styled observation.

The nuisance family is deliberately basic and bounded. Passing it would not
establish camera, RAW, HDR, scanner or arbitrary prior-grade canonicalization.

## Frozen information regimes

1. **seen-look hard retrieval**: reference operators exist in the development
   bank, but the query content group is new;
2. **unseen-look regression**: the query base direction is absent from model
   fitting, nearest-neighbour bank construction and normalization fitting;
3. **single output-only reference**: one styled reference observation;
4. **four output-only same-look references**: four unrelated styled reference
   observations aggregated symmetrically;
5. **paired-reference upper bound**: exact pre-look and post-look observations
   for one content group.

Development and held-out groups are fixed before fitting. Descriptor
normalization and ridge regularization are fitted only on direction `0-23`,
content-group `0-3` observations. PCA is not authorized in W1D. The
confirmation look directions, content seeds and nuisance seeds remain
untouched.

## Frozen methods

The first implementation must remain deliberately simple:

1. identity operator;
2. global mean operator over development looks;
3. raw marginal RGB-histogram nearest neighbour, as a content-shortcut
   negative control;
4. categorical fixed-descriptor hard retrieval, as a strength-splitting
   control;
5. hard direction retrieval with continuous piecewise-linear strength in
   parameter space;
6. fixed factorized descriptor ridge-to-operator regression;
7. paired-reference bounded O0 fit, as a non-product upper bound.

The fixed descriptor may contain only spatially invariant, preregistered
statistics: log-luma quantiles, chroma-by-luma summaries, cyclic hue moments,
neutral-axis summaries and shadow/midtone/highlight channel relations.
Semantic labels, scene embeddings, CLIP, geometry, filenames, source identity
and generator IDs are forbidden.

No neural encoder is permitted in W1D. A small parameter-only model may be
proposed later only if the fixed descriptor establishes that the required
information exists and simple regression is insufficient.

## Evaluation

All predicted/retrieved recipes are converted to the existing U5.R2O0
cube-preserving flow and evaluated in float64.

Primary evidence:

- hidden operator output RMSE on the frozen uniform grid;
- p90 operator output RMSE;
- same-look/different-content replicate operator RMSE;
- unseen-direction generalization;
- seen-look retrieval accuracy;
- identity-reference false-positive error;
- strength-direction cosine and strength ordering;
- content/nuisance association of the inferred look signature;
- output range, Jacobian determinant/spectral norm, inverse and replay;
- diagnostic descriptor distance under OOD generated content. A calibrated
  abstention threshold is a later conditional child: it is not fit in W1D
  unless a practical operator method first passes the frozen recovery,
  nuisance and structure gates.

Distribution or histogram similarity is diagnostic only. A result that
matches reference marginals while missing the hidden operator fails.

## Development gates

The primary fixed-descriptor method must:

- achieve grid-output RMSE median `<= .07` and p90 `<= .10`;
- achieve same-look replicate operator RMSE median `<= .04`;
- improve median operator error by at least 25% over both identity and global
  mean;
- keep identity-reference grid RMSE `<= .01`;
- preserve strength ordering with Spearman `>= .90`;
- preserve same-direction cosine `>= .95` for the `53/55/56` fixture;
- keep content-group and nuisance-family prediction from the inferred look
  signature at no more than chance plus ten percentage points under
  group-held-out evaluation;
- pass all inherited range, Jacobian, inverse, coefficient-norm and replay
  gates.

The raw-histogram negative must not be promoted even if it retrieves a look
under content-confounded data. Its nuisance association and cross-content
replication are mandatory diagnostics.

These are development gates. Confirmation gates and seeds remain frozen but
unexecuted until the development branch is adjudicated.

## Decision branches

- **seen retrieval passes, unseen regression fails**: retain only a bounded
  case-bank/reference-bank route;
- **single output-only passes**: retain a single-reference challenger;
- **single fails, multi-reference passes**: require multiple references;
- **only paired upper bound passes**: close practical reference inference as
  unidentified;
- **content or nuisance control fails**: close the descriptor without adding
  capacity;
- **simple regression passes unseen directions**: open an untouched
  confirmation before considering a small parameter-only predictor;
- **structural or replay gate fails**: invalidate and debug only the explicit
  operator boundary;
- **all practical methods fail**: retain the global deterministic champion;
  do not reinterpret synthetic failure as evidence about whether real film
  stocks exist.

## Real-data stop

A synthetic pass does not authorize use of the current film pools. Real
reference-look work needs a separate manifest/rights/lineage decision and
repeated same-look groups whose grouping is independent of content and source.
Current Commons/YFCC film pools fail stock identifiability and are forbidden.
The partial FiveK freeze is not film truth and requires its own restore,
lineage and allowed-use decision before even an auxiliary content-only test.

Professional blind review, external recruitment, paid data, commercial
baselines and public model release are also outside W1D.

## Claim ceiling

At most, W1D can establish that a specified fixed descriptor plus explicit
operator bank/regressor can or cannot recover generated bounded look
operators across independent generated contents. It cannot establish a film
stock response, calibrated reference match, real grading reconstruction or
general unpaired digital-to-film operator.
