# U7.9B — Private Runtime Canon RAW Compatibility Contract

## Question

Does the exact repository-bound, binary-only Windows product runtime admitted by
U7.9A reproduce the current direct product chain and the frozen P314 output
oracle for all six exact P313 Canon sRAW/mRAW inputs?

## Parent and novelty boundary

- P313 already proves generic `WorkingImage` ingress for the six exact files.
- P314 already proves the current public CLI, Ektar 100 Look Approximation,
  strict recipe creation and exact recipe replay for the same six files.
- U7.8C already evaluates a real-scale batch transaction and remains an
  immutable negative; this leaf does not rerun or reinterpret it.
- U7.9A proves the create-only binary-wheel installation, receipt, launcher and
  all three product looks only on a 23x17 procedural PNG. It does not prove that
  the installed runtime includes a working real-RAW dependency path.
- U7.9B changes no product core, decoder, profile, recipe schema, installer,
  launcher, dependency pin, source, look or output format. It composes existing
  public/private interfaces only.

The sole new claim is exact six-file compatibility of the installed runtime.
It is not new RAW support, transaction repair, stock evidence or a public
package claim.

## Frozen inputs and execution

- Sources: the six exact rows, sizes and SHA-256 identities in the P313
  contract.
- Runtime: a fresh U7.9A installation made from the existing repo-relative,
  P-backed `tmp/u7_9a_wheelhouse_v1` with network disabled.
- Direct control: the current repository `.venv` product CLI.
- Explicit look: `ektar_100`, amount `1.0`, product profile
  `safe-rich-product-v1`.
- Effects: grain, halation and dust all zero.
- Output: deterministic 8-bit sRGB PNG plus strict recipe.
- For every row, the direct control and installed launcher render sequentially
  to the same logical output path under an owned repo-relative P-backed scratch
  root. The direct artifacts are hashed and removed before the launcher run so
  path-bound recipe bytes are directly comparable without normalization.
- The installed runtime replays its strict recipe to a distinct create-only
  target through the existing replay entrypoint, and that replay must equal the
  launcher output byte for byte.
- The direct and installed output SHA-256 must also equal the immutable P314
  Ektar output oracle for that source.
- Formal execution is two fresh committed-head controller processes, forward
  and reverse source order. Reports use canonical `source_id` order.

## Required gates

1. The committed worktree is tracked-clean before installation and execution.
2. U7.9A, P313 and P314 evidence/config bindings are exact.
3. All six source paths, sizes and SHA-256 identities are exact and remain
   immutable.
4. The wheelhouse contains exactly the frozen U7.9A binary wheels and the fresh
   install receipt has the exact pinned distribution set with `pip check`
   passing and OmegaConf/ANTLR absent.
5. Direct and installed-launcher CLI runs return zero for all six rows.
6. Direct and installed PNG bytes and strict recipe bytes are pairwise exact.
7. Every installed recipe retains the explicit Ektar Look Approximation claim,
   exact input/output/profile identities and current committed software ID.
8. Installed recipe replay returns and publishes the same output SHA-256 and
   bytes as the installed launcher.
9. Every row's output SHA-256 equals its immutable P314 oracle.
10. Forward and reverse canonical reports are byte-identical.
11. Network access is disabled; all runtime, media, cache and process-temp
    artifacts stay under owned repo-relative P-backed scratch and are removed.
12. Missing wheel, source drift, foreign existing destination and invalid
    installed launcher controls fail closed without overwriting foreign data.

## Stop rule

Any failed gate closes this exact U7.9B leaf. Do not replace a source, change
the look, reduce the cohort, alter dependency versions, use the host interpreter
inside the installed path, normalize recipe bytes, relax identity, modify the
installer/renderer/replay engine, permit network fallback or rerun after seeing
the result.

## Claim ceiling

At most: private Windows CPython 3.12 repository-bound binary-only runtime
compatibility for six exact CC0 Canon sRAW/mRAW files through the existing
Ektar 100 `film-inspired / Look Approximation` chain and strict recipe replay.
This is not general Canon/sRAW support, vendor-exact colour, camera or film
calibration, scene-to-display quality, calibrated Ektar response, a standalone
or public installer, product release, transaction recovery or multi-stock
evidence.
