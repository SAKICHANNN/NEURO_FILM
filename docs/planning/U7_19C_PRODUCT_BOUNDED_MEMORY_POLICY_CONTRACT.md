# U7.19C — Product bounded-memory execution policy

## Purpose

U7.19B remains an immutable negative for the default full-frame public CLI path:
the exact Hasselblad X2D `.3fr` and `.fff` representatives crossed the frozen
16 GiB process-tree limit. U7.19C tests a distinct product repair: make the
already-proved exact safe-Lab tiled executor the fixed internal default for the
`safe-rich-product-v1` Look Approximation profile when no explicit tile policy
is supplied.

This is not a rescue of U7.19B. It changes product execution policy, not its
source, result, gate, or report.

## Frozen policy

- Internal default tile size: `256`.
- Internal default tile workers: `1`.
- The values are inherited from the pre-existing U7.18A desktop preview and
  baseline policy; they are frozen before any U7.19C X2D render.
- An explicit existing `--tile-size` / `--tile-workers` request remains
  authoritative and is not silently rewritten.
- The policy applies only to validated `safe-rich-product-v1` rendering and
  replay. Legacy/research profiles and analytic renderers remain unchanged.
- Resource policy is execution metadata, not colour science; recipe colour,
  effect, claim, input, output, profile, and software identities remain
  unchanged.

## Frozen observations

Use the exact U7.19B representatives and no replacements:

- `.3fr`: `x2d_3fr_a`, SHA-256
  `dcc5a4abe3498e6f25e89bb491995fd12c3b669d9277c71b45b49210d3e56280`.
- `.fff`: `x2d_fff_a`, SHA-256
  `44c38665694e07baf47f1fc34fb9ea0f1bf70eb71b7390183d3c0ef23d164e0f`.

Each observation uses the unchanged public CLI, Ektar 100 Look Approximation at
amount `1.0`, `safe-rich-product-v1`, full `8842x11904` resolution, PNG8, strict
recipe, and strict replay. No downsampling, crop, source replacement, effect or
look change is allowed.

## Gates

For both extensions and both forward/reverse process orders:

1. source identity and dimensions are exact;
2. CLI and replay resolve the fixed `256/1` internal policy without an explicit
   command-line tile request;
3. peak owned process-tree RSS is at most `17,179,869,184` bytes (16 GiB);
4. wall time is at most 1,800 seconds per CLI or replay worker;
5. CLI output is an RGB PNG8 with the expected sRGB ICC profile;
6. recipe claim remains `film-inspired / look-approximation`, with calibrated
   reference forbidden;
7. replay output is byte-identical to the CLI output;
8. source files remain immutable, network requests are zero, and owned scratch
   residue is zero;
9. forward/reverse scientific identities are exact.

## Stop rule

The fixed `256/1` policy is the only candidate. Any resource, identity,
render, replay, atomicity, or cleanup failure closes U7.19C. Do not change the
tile size, worker count, resource gate, timeout, source, format, look,
resolution, recipe, or replay path after observing a result.

## Claim ceiling

A pass establishes only a private, exact two-file Windows/Python
bounded-memory product execution mechanism for the existing deterministic
Look Approximation renderer. It does not establish generic Hasselblad,
`.3fr`/`.fff`, RAW colour, demosaic quality, pixel-shift fusion, calibrated
stock response, physical-film reproduction, arbitrary-host performance,
public release, or product-value evidence.
